Note à Note · Developer handbook

How the app works, and how to change it

Everything you need to change Note à Note on your own. It assumes you can edit HTML, CSS and a little JavaScript. The app's interface is in French; this handbook and the code comments in it are in English.

Live site: yannickriou.github.io/solfege · Repository: github.com/YannickRiou/solfege

1. Principles

  • No build step, no dependencies. The browser loads index.html, css/style.css and the modules in js/ as they are. What you see in the repository is exactly what gets published.
  • Plain modern JavaScript (ES modules, import/export), no framework. Each screen is an HTML string injected into <main id="app">.
  • No data leaves the browser. No server, no accounts, no analytics.
  • The curriculum is data. Adding a lesson means editing an array in js/curriculum.js and nothing else.

2. Files

index.html            the single page: loads the fonts, the CSS and js/app.js

Module dependencies: app → curriculum, exercises, scheduler, storage; exercises → notation, audio. Only app.js touches the DOM when it loads. The other modules can be imported in Node, which is what makes them testable.

3. Running locally

python -m http.server 8000      # or: npm start

Open http://localhost:8000. After a change, reload the page (Ctrl+Shift+R to bypass the cache).

To start from empty progress, use the Remettre à zéro button at the bottom of the home screen, or run this in the browser console: localStorage.removeItem('solfege.progress').

4. The note model

A note is a step: octave × 7 + letter, where letter 0 = do (C), 1 = ré (D) … 6 = si (B). Octave numbers follow the French convention: middle C is do3 (C4 in English notation).

StepNoteEnglishPosition on the treble staff
28do3 (middle C)C4first ledger line below the staff
29ré3D4just below the bottom line
30mi3E4bottom line
32sol3G42nd line (the one the clef curls around)
34si3B4middle line
35do4C53rd space
38fa4F5top line
40la4A5first ledger line above the staff

Useful helpers in js/notation.js: noteName(28) → "do", frName(28) → "do3", midiOf(28) → 60, letter(35) → 0.

The limits are constants: STAFF_LOW/STAFF_HIGH (notes that can be drawn on the staff) and KEY_LOW/KEY_HIGH (the 14 white keys of the on-screen keyboard, do3 to si4).

The two keyboard exercises key and keyname work on letters (0 to 6), so the octave doesn't matter. Every other exercise works on steps.

5. Recipes

Add or change a lesson

In js/curriculum.js, add an object to a unit's lessons array:

{ id: 's5', title: 'Les notes sur les lignes', types: ['name', 'place'], items: [30, 32, 34, 36, 38],
  hint: 'Mi, sol, si, ré, fa : de bas en haut.' },

Rules, all checked by npm test:

  • id must be unique. Never rename the id of a published lesson: users' saved progress refers to it.
  • types are keys of EXERCISES (see the table below). All types in one lesson must use the same kind of items: steps or letters.
  • items: at least 2 notes, within the limits (28 to 40 for steps, 0 to 6 for letters).
  • hint is optional. It is shown under the question.

The order of the file is the order of the path: a lesson unlocks when the previous one is finished. If you insert a lesson in the middle, it is locked for users who are already past that point until they finish it.

nameSees a note on the staff, picks its namereadsteps

findstaffPicks, among 3 staves, the one showing the requested notereadsteps

Add a unit

Add an object { title, sub, lessons: [...] } to UNITS. The unit number shown on the home screen is computed automatically.

Change lesson length or points

At the top of js/app.js: QUESTIONS (questions per lesson), XP_PER_ANSWER, and PRACTICE_DAY (how many free-practice answers count as a day for the streak).

Tune spaced repetition

In js/scheduler.js, every (skill, note) pair has a weight that starts at 1. A wrong answer sets it to weight × 2 + 1 (capped at MAX), a right answer to weight × 0.7 (floored at MIN). Notes are drawn in proportion to their weight. To bring mistakes back faster, raise MAX; for more variety, narrow the gap between MIN and MAX.

How free practice works

Free practice never ends. For each question, app.js picks a random lesson among the unlocked ones, then one of that lesson's exercise types, then a note according to the weights. It therefore grows on its own as the learner progresses. To open it to the whole curriculum from the start, replace unlockedLessons() with ALL in newQuestion().

Add an exercise type

1. In js/exercises.js, add an entry to EXERCISES:

octave: {
  title: 'Grave ou aigu ?',        // shown under lesson titles on the home screen
  skill: 'read',                   // 'read', 'key' or 'play': used by spaced repetition
  items: 'step',                   // 'step' or 'letter' (0 to 6)
  make: ({ lesson, pick }) => ({ item: pick() }),
  render: q => ({
    prompt: 'Ce do est-il grave ou aigu ?',
    body: paper(staffSVG({ notes: [{ step: q.item }] }))
      + `<div class="choices two">
           <button class="choice" data-input="octave" data-v="0">Grave</button>
           <button class="choice" data-input="octave" data-v="1">Aigu</button>
         </div>`,
  }),
  input(q, el, root) {
    if (el.dataset.input !== 'octave') return null;   // not our click: ignore it
    const ok = (+el.dataset.v === 1) === (q.item >= 35);
    add(el, ok ? 'hit' : 'miss');
    return { ok, msg: ok ? 'Exact.' : 'Regarde où se trouve la note par rapport à la clé.' };
  },
},

2. Use it in a lesson: types: ['name', 'octave'].

3. Run npm test. The test “each type produces a displayable question” tries your exercise on every lesson that uses it.

The contract (also summarised at the top of exercises.js):

  • make receives pick(exclude?), which draws a note from the lesson according to the weights. Put everything the display needs into the question object (options, sequence…).
  • render returns the prompt and the HTML. Every clickable element carries data-input: the app forwards those clicks to input.
  • input returns null while the exercise is still going (multi-step exercises such as place or melody), otherwise { ok, msg }. msg is shown after “Bravo !” or “Raté.”. To grade several notes at once, add results: [{ item, ok }, …].
  • onKey is optional and receives computer-keyboard events.

Helpers already available: staffSVG({ notes, zones, clef, width }), keyboardHTML({ mark, target, interactive }), nameChoices(), paper(svg), add(el, 'hit' | 'miss'), tone(midi).

Change the look

Colours, font and corner radius are variables at the top of css/style.css. The @media (prefers-color-scheme: dark) block redefines the same variables for dark mode, so every new colour must be declared in both blocks.

The --paper-* and --key-* variables are for the staff and the keyboard, which stay light in both themes, like sheet music and a real piano.

Fonts: Atkinson Hyperlegible (text, designed for legibility) and Noto Music (treble clef), both loaded from Google Fonts in index.html.

Make the keyboard bigger

Change KEY_LOW / KEY_HIGH in js/notation.js; key widths adapt. On a phone, more than 14 white keys become hard to tap.

Change the saved data

Progress is a JSON object stored under the key solfege.progress:

{ v: 1, xp, streak, lastDay: 'YYYY-MM-DD', bestCombo,
  lessons: { s1: { done: true, best: 9 } },
  items: { 'read:30': { w: 2.4 } } }        // spaced-repetition weights
  • Adding a field: add it to blank() in js/storage.js. Existing saves get it automatically with its default value.
  • Changing the shape of an existing field: increment SCHEMA and write, inside load(), the conversion from the previous version.

Without that conversion, users lose their progress: a save from another schema version is ignored.

6. Tests

npm test

Node.js 20 or later, nothing to install. Covered automatically: note conversions, curriculum consistency, generation and rendering of every exercise in every lesson, spaced repetition, saving and the day streak.

Not covered, so check by hand before publishing a visible change:

  • On a phone, or in dev tools at 375 px wide: the keyboard and the 7 note buttons fit with no horizontal scrolling.
  • In dark mode: text is readable, the staff and keyboard stay light.
  • Each exercise type you touched: right answer, wrong answer, feedback shown, Continuer button.
  • Sound plays on the first click (Safari and iOS included).
  • After a reload, XP, streak and finished lessons are still there.

7. Deployment

GitHub Pages serves the main branch, root folder (Settings → Pages). Every push to main republishes the site within a minute or two; progress is visible in the Actions tab (“pages build and deployment”).

The .nojekyll file turns off GitHub's Jekyll processing, so files are served as they are.

8. Known pitfalls

  • Blank page when opening the file directly: ES modules need a server (see Running locally).
  • A change doesn't show up: browser cache. Press Ctrl+Shift+R, or wait for the deployment to finish.
  • No sound: browsers block audio until the first click. On an iPhone, also check the silent switch.
  • Lost progress: private browsing, or cleared site data. Progress belongs to one browser on one device.
  • A mistake in curriculum.js breaks the whole site: run npm test before pushing.

9. Ideas

  • Bass clef: one more unit; needs a second clef drawing and shifted positions in staffSVG.
  • A “do ré mi” / “C D E” naming switch.
  • MIDI keyboard input (Web MIDI API, Chrome and Edge) or microphone pitch detection.
  • Sharps, flats and black keys.
  • Offline use (service worker).
